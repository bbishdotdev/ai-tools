# Model launcher and doctor

## Contract

The private `.bstack/model-clis.json` supplies argv templates for selected Codex, Claude Code, Cursor and Grok CLIs. A wrapper such as `launch claude -- {args}` must receive the native flags as separate arguments; no shell evaluates the template. A bad wrapper must be named rather than retried as the plain binary. This configuration does not change the selected model or grant account access.

Normal package `doctor` must keep basic installation usable while reporting optional launcher status. `doctor --live --workflow review-pr|grilling|to-pr` sends small prompts only for the selected workflow and fails when a required CLI role cannot answer. The review runner checks its roles again with its exact structured-output flags before full model work. Autonomous grilling's default preflight blocks planning writes on a broken CLI role. A native-host grilling role needs an observed host-level check; a structural check must not be reported as live proof. The `to-pr` text probe does not certify Codex image generation.

## Drive

Use a disposable consumer project and configure a fake wrapper whose first arguments are `launch`, the CLI name and `--`. Confirm its recorded argv contains the native model and effort flags after the separator. Test missing executable, unavailable model, malformed template, and a valid live response. Repeat package `doctor` twice and confirm package integrity remains valid with no generated bytecode.

With model usage authorized, install the built release into a throwaway project, then run live doctor for review and grilling roles. Record the requested model, observed response, and whether the CLI exposed an independent model identity. Exercise each supported CLI adapter separately; a passing text answer proves only that prompt path at that time. For `to-pr`, attempt and inspect an actual generated image before claiming image-tool coverage. Keep local evidence under gitignored `.bstack/verification/`.
