Common starting points

What are you doing today?

These are paths you can take, not boxes you need to check. Skip anything that adds no value.

01 / engineering

Find the cause. Fix the cause.

A clear bug can go straight into engineering. PStack's code investigation and BStack's baseline push the agent past test-only fixes and patches that hide the problem.

No map, spec, or ticket required
how · whyif context is missing→poteto-modeor auto routing→root-cause fixbehavioral checks→to-prwhen ready

Relevant ADRs come into context if they explain an existing choice.

02 / planning to build

Get clear before you commit.

Matt's questioning and Wayfinder approach help settle the unknowns. BStack keeps the work local and hands the accepted direction to engineering in a fresh context.

Use only the steps the idea needs
grill-mesurface decisions→wayfindermap open questions→prototypecompare options→spec · ticketsslice accepted work→handofffresh context→implementengineering workflow

A consequential architecture choice can become a short ADR. Routine picks don't need one.

03 / review and delivery

Make the change easy to judge.

BStack's PR skills keep the explanation short, challenge the code with independent reviewers when available, and test feedback before turning it into more work.

An existing PR can start at review
to-prnew PR briefing→review-prindependent challenge→resolve-prjudge feedback

A reply can be enough. Not every review comment calls for code changes.

04 / understanding

Know the code before touching it.

Ask how a subsystem works, why it was shaped that way, or for a plain explanation. These entries can be used without starting an implementation.

Read-only understanding is a valid outcome
howwhat the code does·whythe reasons behind it·teachthe fuller picture

BStack's ADR process helps separate recorded decisions from the agent's guesses.

The work survives the chat

Pick up without starting over.

Agents can change, models can change, and a task can move from planning to implementation. What matters should have somewhere durable to live.

01

Project baseline

Seven shared engineering rules live in project instructions. They apply even when automatic routing is off.

02

Work and decisions

Local Wayfinder maps, specs, and tickets hold the active work. Important architecture decisions live in repository decision records (ADRs).

03

Handoffs

Accepted scope, evidence, and decision links can move to a fresh context before the next phase or model takes over.

04

Optional personal memory

Approved personal preferences can carry across Codex, Claude Code, and Cursor. Project facts stay with the project.

Under the hood, briefly

How does it stay lean?

BStack ships one reviewed package, but your agent only reads the parts the current task needs.

01 / install

One package, selected tools

The installer gives each selected host direct skill entries pointing at the same local package. It does not fetch new upstream skills during setup.

02 / choose

Manual first, auto if you want it

Call a skill by name, or opt into bstack-auto for ordinary engineering prompts. A short router reminder does not dump every playbook into context.

03 / carry forward

Keep the right context

Local work, ADRs, and handoffs carry decisions forward. A workflow uses supported host capabilities and calls out what is missing.

Try it

Start with the work in front of you.

Already installed? Ask your agent “How do I use BStack for this task?” or invoke bstack-guide. You can use a named skill without enabling automatic routing.

Need to install it?

Install the small entry skill, then ask your agent to install the full bundled package in your project.

npx skills add bbishdotdev/ai-tools --skill install-bstack

A release ZIP works without skills.sh. Both routes install the reviewed package.
