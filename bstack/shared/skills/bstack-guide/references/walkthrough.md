# A short bstack walkthrough

Teach from the person's task. This is a map for the agent, not a script to recite or a list to print in full. Bstack builds on pinned work from PStack and Matt Pocock, then connects it with its own project baseline, local workspace, ADR process, handoffs, and optional memory. Use the package's `README.md` for current limits.

- **When a developer changes tools:** One project installation exposes the same BStack skill names and package to its selected Codex, Claude Code, Cursor, and Grok hosts. A developer can plan in one and continue in another using saved workspace records and a `handoff`, instead of hoping the new chat remembers an old conversation. After an install or upgrade, a new session may be needed to discover skills.
- **When a bug lands:** The seven-rule baseline is already in project instructions, even with auto routing off. It steers the agent toward the root cause, a considered implementation change, and meaningful behavioral tests. `unslop` keeps the explanation readable. A clear bug can go straight to engineering; it needs no map, spec, or ticket first.
- **When a feature is still fuzzy:** `grill-me` can surface decisions; `wayfinder` can keep the open questions in the local workspace; `prototype` can compare directions. Once choices are accepted, `to-spec` or `to-tickets` can make the work buildable. `handoff` carries the accepted scope and evidence into a fresh implementation context, including another model when the host supports it. The developer can skip any artifact that would add no value.
- **When a design choice matters later:** Bstack's ADR process records only consequential decisions in the repository. An agent checks relevant ADRs before proposing an approach, so it can respect a prior rejection or explain why new evidence warrants revisiting it. Routine UI picks and small code choices do not need ADRs.
- **When personal context matters across tools:** Optional shared memory can carry approved personal preferences across Codex, Claude Code, and Cursor. It is separate from the project baseline, ADRs, and Wayfinder records; project decisions belong with the project. Installation does not turn memory on.

Manual engineering routing is the default. `poteto-mode` selects a workflow when invoked; `bstack-auto on` lets ordinary engineering prompts enter that router. Neither mode grants product-decision authority or loads the whole skill collection into every prompt. A question about BStack can select this guide in either mode.

For a tour without a task in mind, connect the bug and feature examples above to one route from [common routes](routes.md). Stop once the person can see where to start, and let them choose where to go deeper. Don't imply that an external tracker, model role, desktop skill catalog, or personal memory is already configured.
