# Setup when a workflow needs it

BStack's local planning, tickets, basic engineering skills, and manual grilling do not need a model-role picker or an external tracker. Install the package, select the agent hosts you use, and start a fresh agent session so its skill catalog refreshes. New installs enable automatic routing; upgrades keep the previous choice. `bstack-auto off` leaves named skills available.

Check a requirement when the requested workflow needs it. Explain what the missing tool does, why this step needs it, and the smallest way to proceed. Basic installation does not require optional integrations. For an explicitly requested full setup, offer PR review, PR visuals, and grilling model configuration before concluding. Show the effective model choices and efforts before offering to keep or change them. Honor workflows already chosen and avoid a separate picker for every model. Grilling models can be saved and tested for later while work stays human-guided; setup does not start an autonomous interview.

| When you do this | What you need | If it is missing |
| --- | --- | --- |
| Use local Wayfinder, specs, or tickets | A writable project directory and Python 3 | Report the local filesystem or Python problem. No Jira, Linear, or GitHub account is needed. |
| Publish, edit, review, or resolve a GitHub PR | A Git remote, an authenticated `gh` CLI, and access to that PR | Keep local preparation or feedback; explain that posting to GitHub is unavailable. Do not pretend a local comment was published. |
| Run `review-pr` with independent reviewers | Authenticated reviewer CLIs with a read-only headless mode, and usable models. | Run `review.py doctor --live`. It checks logins, selected models, and that each role can read the snapshot. No MCP server, browser setup, or OS worker is required for static review. |
| Run an app or tests during PR review | A fixed project check and a separate, credential-free runtime worker configured in `.bstack/review.json` | Leave runtime verification unconfigured to use static review. Do not run untrusted PR code on the host as a fallback. |
| Run autonomous grilling | Two distinct accessible model participants configured through `shared/workflow.py configure-grilling` | Run `bstack.py doctor --live --workflow grilling` before planning writes. Continue with human-guided grilling if a role cannot answer. Native host participants still need a host-level check; the CLI doctor cannot certify them. |
| Ask `to-pr` to generate an image through Codex | A permitted, authenticated Codex launcher | Run `bstack.py doctor --live --workflow to-pr` before the visual attempt. This checks a text prompt, not image-tool access; inspect the actual visual and use the documented fallback if the image tool is unavailable. |
| Use an imported multi-model engineering workflow such as Arena or Interrogate | A host-supported way to delegate and models accessible on that host | Inherit the parent's model for an ordinary delegate when appropriate. State clearly if independent-model comparison could not happen. Ignore upstream Cursor model files and fixed provider names. |
| Run an imported helper | Its documented local runtime and any specific service it uses | Check the helper before use. Do not install Bun, Graphite, Tailscale, or a cloud service just because a pinned source mentions it. |
| Create or maintain a project verifier | A real app path to exercise and the project's verification setting | `off` skips verifier edits, `ask` proposes a concrete change, and `auto` maintains the affected recipe. If the app cannot run, record the limit and run the available checks. |

The `quarantined_playbooks` in the installed `index.json` are not active. Their implementations remain in the pinned development sources and are excluded from the consumer bundle. Do not revive their watcher, cleanup, cloud, or orchestration helpers through a fallback guess. Use the owned `worktree-cleanup` skill for a portable worktree audit. Offer a supported narrower workflow and state which capability would have to be ported.

## Explain the work before launching

Arena produces competing versions of the requested artifact, compares them, and combines the strongest parts into one result. Interrogate reviews existing work from independent perspectives and returns findings; it does not apply fixes. Explain that distinction when helping the user choose. For Arena, name whether the candidates will produce proposals, prototypes, or implementation, using the scope already authorized. Asking for ideas does not authorize code changes.

Before launching either workflow, state the candidate or reviewer count, any separate judge, and the actual models or inherited-model policy the host supports. Name model identities only when available; do not guess an underlying model from an Auto setting. Explain that several attempts consume more model usage than one. Same-model attempts are separate attempts, not evidence of model-family diversity. Use existing model choices and scope without asking again; ask only when a missing choice changes what can actually run. The PR review and grilling role settings do not configure Arena or Interrogate.

## Check the selected tools

Host hook setup differs. Claude Code, Cursor, and Grok can load their configured project hooks in a fresh session. Codex requires hook support to be enabled and local hook trust to be reviewed. A passing package `doctor` check confirms installed files and bindings, not live hook delivery, model access, or a full workflow run. Run the relevant live verification before claiming those behaviors work.

Before a selected workflow's first live check, reuse saved launch commands or commands already established in the session. Otherwise ask for the actual working headless terminal command for each required CLI. Examples are `claude -p "say hi"`, `codex exec "say hi"`, and `launch claude -- -p "say hi"`. Request command syntax only, never credentials or complete settings files. BStack supplies the prompt, model and output flags, so save only the executable and wrapper arguments around `{args}`.

For a wrapped CLI, use `python3 .bstack/package/shared/model_cli.py --project "$PWD" configure --cli claude --command 'launch claude -- {args}'`, replacing the command with the developer's real launcher. The plain equivalent is `claude {args}`. BStack inserts native arguments at `{args}` without a shell. This private setting applies to model probes, PR reviews and Codex PR visuals. Run the selected workflow's live doctor after changing it; do not silently retry the plain binary or switch models.

If the normal terminal command authenticates but BStack's call does not, say that BStack could not use the working login and check its launch command and settings. That result does not establish logout. An incidental certificate warning is not enough reason to edit certificates, shell files or login settings. Name the failed step and give the smallest useful next check. Report basic installation and each selected workflow separately as passed, not checked, or blocked. Ordinary setup stays usable when an optional model workflow is unavailable, and a passing `to-pr` text probe still leaves image generation unverified.
