Who starts what

What do I invoke myself?

Routing picks work for the current request. It does not commit you to every card in the feature example.

Default / manual

Name the skill you want

The seven-rule project baseline and unslop are present. Invoke a skill directly for a focused job, such as grill-me, wayfinder, or to-spec.

Example: asking for a prototype starts a prototype. It does not create tickets or implement the choice afterward.

Manual engineering route

Invoke poteto-mode

Poteto Mode selects one matching engineering playbook. That playbook can load relevant how, architect, principles, or review steps.

Example: a bug fix can enter the Bug fix playbook. The planning sequence is not a prerequisite.

Opt-in auto mode

Describe the task normally

bstack-auto on lets ordinary engineering prompts enter the same router. It can suggest or select the SDLC phase that matches your request, within the scope you gave it.

Example: “fix this bug” can route to Bug fix. It will not silently decide product questions, build a whole Wayfinder map, then publish a PR.

Across all three: a named skill may call its documented dependencies, but later phases are separate decisions. implement hands accepted work to the engineering router; to-pr runs when PR delivery is authorized; review-pr and resolve-pr are separate PR jobs. Auto mode changes routing, not decision authority.

What actually connects?

Solid relationships happen inside a selected skill. Later phases are choices unless your request already authorizes them.

Loads its method

grill-me → grilling   ·   grill-with-docs → grilling + domain-modelingThose supporting skills are read when you invoke the entry.

Dispatches per question

wayfinder → grilling, research, or prototypeOnly for the question being worked, its method, and the authority you gave.

Routes engineering

implement or poteto-mode → BStack router → one matching PStack playbook → needed skills and principlesWith auto mode on, an ordinary engineering request can enter the same router.

Does not auto-chain

wayfinder ⇢ to-spec ⇢ to-tickets ⇢ implement   ·   to-pr ⇢ review-pr ⇢ resolve-prThose are possible next jobs, not a pipeline that runs just because the previous skill finished.

The work survives the chat

Pick up without starting over.

Agents can change, models can change, and a task can move from planning to implementation. What matters should have somewhere durable to live.

01

Project baseline

Seven shared engineering rules live in project instructions. They apply even when automatic routing is off.

02

Work and decisions

Local Wayfinder maps, specs, and tickets hold the active work. Important architecture decisions live in repository decision records (ADRs).

03

Handoffs

Accepted scope, evidence, and decision links can move to a fresh context before the next phase or model takes over.

04

Optional personal memory

Approved personal preferences can carry across Codex, Claude Code, and Cursor. Project facts stay with the project.

Under the hood, briefly

How does it stay lean?

BStack ships one reviewed package, but your agent only reads the parts the current task needs.

01 / install

One package, selected tools

The installer gives each selected host direct skill entries pointing at the same local package. It does not fetch new upstream skills during setup.

02 / choose

Manual first, auto if you want it

Call a skill by name, or opt into bstack-auto for ordinary engineering prompts. A short router reminder does not dump every playbook into context.

03 / carry forward

Keep the right context

Local work, ADRs, and handoffs carry decisions forward. A workflow uses supported host capabilities and calls out what is missing.

Try it

Start with the work in front of you.

Already installed? Ask your agent “How do I use BStack for this task?” or invoke bstack-guide. You can use a named skill without enabling automatic routing.

Need to install it?

Install the small entry skill, then ask your agent to install the full bundled package in your project.

npx skills add bbishdotdev/ai-tools --skill install-bstack

A release ZIP works without skills.sh. Both routes install the reviewed package.
