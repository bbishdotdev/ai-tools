Docs / overview

bstack

Skills and local tools for planning, building, and reviewing software with agents. Start with the work you have. There's no required pipeline.

Built from Lauren Tan's PStack, Matt Pocock's skills, and BStack's own workflows. Selected agent tools use the same project-local package.

Pick your entry
Investigate code, work through an idea, prototype, implement, or review a PR. You can begin at any of them.
Keep work local
Wayfinder maps, specs, and Kanban tickets live in a private workspace. External tracker adapters are planned, not required.
Carry decisions forward
Handoffs move accepted work to a fresh agent context. Important architecture choices become short repository ADRs.
Use your tools
One pinned package supports selected Codex, Claude Code, Cursor, and Grok hosts. Optional shared memory covers approved personal preferences across supported tools.

Workflows

Common use cases

These are examples, not mandatory sequences. Dashed steps are optional. A later phase starts when you ask for it or the current request already authorizes it.

Find the cause. Fix the cause.

A clear bug can go straight into engineering. Use how or why if you need to understand the existing behavior first. Poteto Mode chooses the matching engineering playbook; the project baseline pushes the fix toward the root cause and meaningful verification.

No map, spec, or ticket required.
how · whyif context is missing→poteto-modeor auto routing→root-cause fixbehavioral checks→to-prif PR delivery is in scope

Relevant ADRs can explain an existing choice before the agent proposes changing it.

Settle what matters before building.

grill-me helps expose assumptions. Use wayfinder when decisions need to survive across sessions, and prototype when a cheap example will help choose a direction. Accepted scope can move through a spec, tickets, or directly to implementation.

Skip steps that add no value.
grill-mesurface decisions→wayfindermap open questions→prototypecompare options→spec · ticketsslice accepted work→handofffresh context→implementengineering workflow

A consequential architecture choice may need an ADR. Routine feature decisions do not.

Make the change easy to judge.

to-pr explains a new PR and checks overlapping work. review-pr challenges it with independent reviewers when the required CLIs are available. resolve-pr checks feedback before making a fix or replying.

An existing PR can start at review.

Reviewers can search the whole saved repository, including unchanged callers. General shell, private-file reads, and arbitrary web requests are disabled through their tools. These restrictions are not an operating-system sandbox. Running your app or tests is a separate optional setup. Feedback explains the problem, its impact, and a concrete next step, with code links underneath.

to-prnew PR briefing→review-prindependent challenge→resolve-prjudge feedback

A reply can resolve a comment. Code changes are not automatic.

Understand before editing.

Use how for current behavior, why for the reason behind it, or teach for a fuller explanation. A read-only answer is a complete outcome.

Behavior

What runs when

New installs enable automatic routing; upgrades keep the project's existing setting. Auto mode helps ordinary engineering requests enter the router. It does not grant authority to make product decisions or run every phase.

Direct skill

Invoke the entry you need

Call grill-me, prototype, how, or another named skill. It reads only its relevant dependencies. The project baseline and unslop still apply.

Poteto Mode

Ask for an engineering workflow

Invoke poteto-mode. The router selects one matching PStack playbook and its needed principles and skills. A bug fix can start here without a Wayfinder map.

Auto routing

Prompt normally

New installs start with this on. An ordinary engineering request can enter the same router, while named skills remain available. Use bstack-auto off if you prefer manual routing. Auto routing does not authorize publishing a PR or deciding product scope.

Try it: ask “Fix the sign-in bug and verify the behavior.” With auto mode off, invoke poteto-mode for its playbook. With auto mode on, the normal prompt can select it.

Context

What survives a chat

Keep project decisions in the project. Keep active work in the workspace. Move only accepted scope and evidence to the next agent or model.

Project baseline

Seven engineering rules go in project instructions, including when auto routing is off.

ADRs

Short repository records capture fundamental architecture choices. Most feature-level decisions do not need one.

Local work + handoffs

Maps, specs, and tickets persist in a private SQLite workspace. Handoffs carry accepted work into a fresh agent context.

Optional personal memory

Approved preferences can carry across Codex, Claude Code, and Cursor. Project facts stay outside personal memory.

Use recall to catch up on a project, reflect to review how a session went, or automate-me to turn repeated preferences into a proposed skill or rule. Their session reader stays within the selected project. Amp thread export needs you to confirm the selected threads first.

Local data

Workspace and operations

The browser app and agent CLI use the same local records. You can plan in Focus or Atlas, then manage implementation tickets on the Kanban board. No account or external tracker is needed.

Start the local app

python3 .bstack/package/workspace/cli.py --project . init
python3 .bstack/package/workspace/cli.py --project . serve --port 4174

Read it from an agent

python3 .bstack/package/workspace/cli.py --project . request workspace.read
python3 .bstack/package/workspace/cli.py request --help

The CLI handles request envelopes, revisions, and saved receipts. Use its operations rather than asking an agent to rewrite database logic.

  • Maps and tickets share the same private SQLite workspace under .bstack/workspace/.
  • Planning and tickets have independent adapter settings. This release implements local operations only; external providers are reported as unsupported.
  • For exact request and response shapes, read workspace/OPERATIONS.md in the bundled package. For agent request examples, read shared/references/workspace-requests.md.

Setup

Install and update

Use the installer skill if you have skills.sh. Then ask your agent to install the bundled package into the current project.

npx skills add bbishdotdev/ai-tools --skill install-bstack

Alternatively, download the bstack release ZIP, extract it, and run its install.py --project /path/to/project. A clone works too. Setup does not fetch the latest PStack or Matt Pocock skills.

Start a new agent session after install or upgrade so the skill catalog refreshes. To update, refresh the installer and ask the agent to upgrade the project. Your selected hosts, auto-mode preference, and verification setting are preserved.

Choose Codex, Claude Code, Cursor, Grok, Amp, Copilot, or OpenCode when installing. Amp, Copilot, and OpenCode use native adapters over the same routing and PR workflows. The compatibility matrix distinguishes recorded CLI checks from pending desktop validation; model quality is tracked separately.

Check or change auto mode

python3 .bstack/package/scripts/bstack.py doctor --project "$PWD"
python3 .bstack/package/scripts/bstack.py auto status --project "$PWD"
python3 .bstack/package/scripts/bstack.py auto off --project "$PWD"
python3 .bstack/package/scripts/bstack.py verification status --project "$PWD"

Check a model workflow before using it

python3 .bstack/package/scripts/bstack.py doctor --project "$PWD" --live --workflow review-pr

Use grilling or to-pr instead of review-pr when that's the workflow you need. The live check sends a short model prompt. If your CLI uses a wrapper, tell the agent its actual launch command once; the bundled INSTALL.md shows how to save and retest it. The to-pr check can't certify image generation until a visual is attempted.

Auto routing is on for new installs and can be turned off. Project verification has separate off, ask, and auto settings. Install integrity and live model behavior are separate checks. For host-specific limits, use the bundled INSTALL.md.
