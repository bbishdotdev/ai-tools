# Reviewer-job security

The PR author controls code, descriptions, comments, and some linked material that the review models read. Treat all of it as untrusted data. The asset to protect is the machine running `review-pr`: its files, credentials, configured CLI sessions, network access, and GitHub review authority. An OWASP check of the contributor's code answers a different question.

The [agent-owasp-compliance skill](https://github.com/github/awesome-copilot/blob/main/skills/agent-owasp-compliance/SKILL.md) is a useful prompt for examining tool use, privilege, trust, and audit trails. Its keyword scan is not a runtime defense. Use the [OWASP Agentic Top 10](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) for the actual risk names and definitions. The referenced skill's short labels do not all match that source.

## Current boundaries

- The runner pins the PR source without executing its tests or hooks. A tool-free preflight checks the full pinned diff, PR description, and discussion before either independent reviewer sees them. The preflight CLI runs with a reduced environment and no model tools; it is still not an OS sandbox. Scanner matches must each receive an explicit clear or hold decision from that judge, so quoted attack fixtures, explanatory PR descriptions or review feedback, and unrelated open PRs do not automatically stop a normal review. Missing decisions fail closed. Direct reviewer instructions in the PR description still require a hold. Agent-rule instructions and changed opaque executables force a hold even if the judge clears them. The runner checks every reported location against the diff. A hold saves a partial result and posts only a runner-written comment for human inspection. It never quotes suspicious source text back into the comment.
- A controlled canary test showed Codex's `--sandbox read-only` role could read a file outside the pinned snapshot. Read-only prevents writes; it does not confine reads to the PR. Claude's restricted role denied that particular read, which is useful evidence but not a universal isolation guarantee.
- Every independent review requires a configured external worker. The runner supplies a reduced environment and checks policy-file, outside-file, and GitHub-credential canaries through that wrapper. The wrapper must enforce file and network boundaries; the runner cannot manufacture those boundaries with a prompt or CLI flag. A preflight pass does not relax this requirement.
- Running a project's app, tests, or verification skill is a separate operation with a separate worker. The command must be selected in trusted local configuration and execute against a disposable copy of the pinned head, without GitHub or model credentials. Enforce file, outbound-network, CPU, memory, and process boundaries in that worker. Do not let PR content choose commands or network destinations. Treat even a clean-looking diff as executable untrusted code.
- The runner checks the PR target before contacting it and caps the diff and model-call budget. The publisher escapes model prose as plain text, including reference-style links, images, HTML, and bare URLs. It creates evidence links itself. These controls reduce abuse but do not make model prose a trusted channel.
- Public review receipts contain reproducible hashes, not signatures. They can prevent duplicate publication by the same account, but no longer skip another checkout's model pass or provide its incremental baseline. Other reviews remain discussion context.

## Before unattended review of hostile PRs

Run the model CLIs in an OS-enforced environment whose readable files are limited to the review snapshot, the installed BStack package read-only, required runtime files, and narrowly scoped authentication. If the package is inside the project, expose `.bstack/package` without exposing `.bstack/reviews`. Restrict network egress and GitHub credentials separately from the models. Run `doctor --live` through each actual launcher and wrapper. The canary checks selected files, not every possible secret or route; verify the worker's mounts and network policy independently. If dynamic verification is enabled, give its separate worker no credentials and no network egress by default. Keep publication in the parent runner after it validates findings against the pinned diff and rechecks the PR head. The callback service must authenticate webhook requests, validate the repository and PR target, and deduplicate delivery IDs.

The preflight is a useful early stop, not a certification that the PR is safe. Prompt injection can evade a judge, and executable code can do harmful work without any prompt instruction. The isolation boundary remains mandatory after a pass. If preflight itself fails, stop. An unverified evidence location becomes a generic, runner-written hold instead of a link to a fabricated line; reviewers still do not proceed.

Maintainers can exercise the live judge without GitHub or real PRs using `python3 -B engineering/review-pr/scripts/security_eval.py --project "$PWD"` from an installed package. The fixtures include normal code and docs, injected instructions in source and PR discussion, and secret-egress attempts. This is a small regression check of one configured model, not a measure of general attack-detection accuracy. The end-to-end tests also cover a held PR posting one sanitized comment and a hostile runtime command running only in a disposable sandbox.
