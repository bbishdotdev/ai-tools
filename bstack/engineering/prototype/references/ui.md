# UI prototype

For an existing feature, show the variants in their real page context inside the disposable checkout. Preserve the surrounding navigation, content density, and component behavior. Stub mutations while keeping representative data. For a new concept, build a standalone sketch with enough context to judge it.

Make options differ in layout, hierarchy, navigation, or interaction. Reuse the established design system without forcing every variant into the same composition. Color or copy changes alone do not create distinct concepts.

Provide one obvious comparison control with stable labels. Keep each option addressable and reloadable where the host permits it. On the web, a URL parameter and a small previous/next bar are useful defaults. Keyboard switching must not interfere with inputs or the interaction being tested. Keep prototype controls visually separate from the proposed design.

When combining options, retain the source variants while the decision is open and give the new combination its own label. Preserve selection and data state when useful for comparison. Reset only when that makes the experiment fair or is part of the requested behavior.
