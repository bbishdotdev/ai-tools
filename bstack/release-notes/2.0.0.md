# bstack 2.0.0

This release makes BStack easier to use from an ordinary prompt and safer to run against an unfamiliar PR. It also removes workflows that still depended on Cursor-specific behavior.

## Breaking changes

- New installations enable automatic engineering routing. Existing installations keep their saved choice. Run `bstack-auto off` if you want to invoke Poteto Mode manually.
- `make-bot-ui`, `automate-me`, `recall`, and `reflect` are no longer in the installable catalog. Seven unported playbooks are quarantined. If you used one of those workflows, check the [selection list](https://github.com/bbishdotdev/ai-tools/blob/v2.0.0/bstack/package/selection.json) before upgrading. The pinned sources remain in the development repository for selective porting.
- PR review now requires an isolated model worker. Optional app verification runs in a separate worker without review or GitHub credentials. A host that cannot provide that isolation must stop instead of falling back to a full-access review.

## Changes

- `review-pr` checks the pinned diff and PR discussion in a tool-free safety preflight. Suspicious instructions, secret access, unexpected outbound calls, and opaque executable changes pause the automated review for a human look. The runner also validates its target, limits model work, sanitizes published text, and checks that a review receipt belongs to the right checkout.
- `to-pr` keeps the briefing short and puts useful visuals beside the explanation they support. The shell PR guard catches direct PR creation that skips the shared PR workflow.
- New installs set project verification to `ask`. Choose `off`, `ask`, or `auto` to control whether feature work creates or updates the affected `verify-<app>` path.
- A shared headless CLI launcher supports local wrapper commands for Codex, Claude Code, Cursor, and Grok. `doctor` can probe the models selected for reviews, autonomous grilling, and PR visuals before those workflows start.
- Setup now explains optional prerequisites when a workflow first needs them. Upgrades can repair a cloned v1 installation whose local state was lost, without replacing unrelated project instructions.

## Upgrade

Refresh `install-bstack` or download this release ZIP, then run the installer in each repository using BStack. Setup preserves selected hosts, automatic-routing preference, and verification setting on existing installations. Start a fresh agent session afterward so the skill catalog and router refresh. Run `python3 .bstack/package/scripts/bstack.py doctor --project "$PWD"` to check the package and bindings; run the model checks before optional multi-model workflows.

## Verification

Package, runtime, transport, installer, layer, shared, GitHub, and release-archive checks passed. A disposable installation and upgrade kept the configured hosts and routing choice. The PR review safety tests cover suspicious diffs and normal security-test changes. Live model access and desktop skill discovery still depend on each user's host configuration.

## Install

Download **bstack-2.0.0.zip** and **SHA256SUMS** from this release. Extract the ZIP and ask your agent to read its `SKILL.md` and install into your project, or run from the extracted folder:

```sh
python3 install.py --project /path/to/my-project
```

Use the same installer to upgrade. Requires Python 3.11+ on macOS or Linux. See [installation](https://github.com/bbishdotdev/ai-tools/blob/v2.0.0/bstack/INSTALL.md) for skills.sh and other options.
