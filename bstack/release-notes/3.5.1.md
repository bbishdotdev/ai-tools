# bstack 3.5.1

Codex PR reviewers start with their optional capabilities turned off again. 3.5.0 removed those restrictions along with the MCP repository browser, which went further than the MCP removal needed.

## Changes

### Fixed

- A Codex reviewer no longer starts with connected apps, plugins, browser and computer use, subagents, hooks, memories, goals, image tools, or skill discovery. This is the list 3.4.1 applied, with one exception: the shell stays on, because without the MCP browser it is the only way Codex can read the snapshot. [PR #45](https://github.com/bbishdotdev/ai-tools/pull/45)
- Commands a Codex reviewer runs get a minimal environment with no provider variables. Each reviewer CLI also starts without the other provider's credentials: Codex does not receive Anthropic or Claude variables, and Claude does not receive OpenAI or Codex ones. `AWS_` variables stay for both, since either CLI can authenticate through Bedrock.

### Changed

- The security overview and the review security reference say that a passing `doctor --live` shows each reviewer can read the snapshot, not that reads outside it are blocked.

## Known limits

A Codex reviewer can still run read-only commands and read any file your user account can read, including credential files in your home directory. BStack does not contain those reads. [ADR 0003](https://github.com/bbishdotdev/ai-tools/blob/v3.5.1/docs/adr/0003-minimal-reviewer-capabilities.md) records the decision to turn off what a review does not need, and that reads stay uncontained. It supersedes ADR 0002.

## Upgrade

Refresh the installer to 3.5.1, run it in each checkout, and start a fresh agent session. No settings change. Rerun `doctor --live --workflow review-pr` to confirm the Codex role still reads the snapshot with your launcher and Codex version.

## Verification

The generated catalog, customization layers, and committed package checks passed, along with the package, runtime, transport, shared, and GitHub test suites. A local test captured the tools Codex 0.171.0 sends to a provider under the review command: its shell, `apply_patch`, empty MCP resource helpers, and a clock. Through the real command, Codex read the snapshot file while two provider-style variables set in its environment were invisible to its shell. The live doctor passed for both reviewers and the adjudicator, and two complete `review-pr` runs against the fix's own pull request finished with the Codex reviewer under these flags.

Not exercised: a managed machine, and Codex versions other than 0.171.0.

## Install

Download **bstack-3.5.1.zip** and **SHA256SUMS**, verify the checksum, and extract the ZIP. From the extracted `bstack` folder, run:

```sh
python3 install.py --project /path/to/my-project
```

Use the same command to upgrade. Requires Python 3.11+ on macOS or Linux. To distribute an extracted release through a folder-based skill installer, select its root `bstack` skill and explicitly run setup. [Installation guide](https://github.com/bbishdotdev/ai-tools/blob/v3.5.1/bstack/INSTALL.md)
