# bstack 3.5.0

PR review no longer needs an MCP server, so it works on machines whose organization blocks them. Reviewers read the pinned snapshot with their own client's read-only tools.

## Breaking changes

- BStack no longer confines PR reviewers to a bundled repository browser. A Claude reviewer gets `Read`, `Grep`, and `Glob` inside the snapshot. A Codex reviewer runs in its read-only sandbox, where it can run read-only commands and read any file your user account can read. Neither can write files or use the network. Decide which PRs are safe to review on your machine; BStack reviews only PRs opened against its own repository, which includes PRs from forks, and still runs the tool-free safety check first. [ADR 0002](https://github.com/bbishdotdev/ai-tools/blob/v3.5.0/docs/adr/0002-client-read-only-review-tools.md) records the choice and what it gives up.

## Changes

### Changed

- Reviewers start with no MCP server at all. [PR #41](https://github.com/bbishdotdev/ai-tools/pull/41) The bundled repository browser, its request trace, and the Codex feature and model-catalog overrides are gone. Review inputs are plain files in the working directory: the base, head, and target trees, `context.json`, and the review policy.
- The live doctor checks that each role signs in, answers, and reads a file from the snapshot. It reports `client_read_only_tools` as the isolation mode.

- The package README opens with what bstack is and does, and ships the supported-tools graphic, for teams that receive only the `release/bstack/` folder. [PR #42](https://github.com/bbishdotdev/ai-tools/pull/42)
- New installs keep the baseline in `AGENTS.md` alone. When the project has no `CLAUDE.md`, setup creates one that imports `AGENTS.md`. An existing `CLAUDE.md` and existing installations keep their managed block. [PR #43](https://github.com/bbishdotdev/ai-tools/pull/43)
- Consumer packages omit maintainer model evaluations and policy test tools, whose synthetic attack strings caused findings in package scans. A packaged `SECURITY.md` explains the files, installation effects, and network behavior. [PR #40](https://github.com/bbishdotdev/ai-tools/pull/40)

### Fixed

- `doctor --live --workflow review-pr` failed with "did not read the expected snapshot probe" when policy blocked MCP servers, and stopped before checking the other roles. The Claude warning that named the cause never reached the user.
- The model doctor could report that Claude was missing required flags because long help output was cut short. It now reads the complete text.
- Running BStack with Python older than 3.11 stopped with a missing `tomllib` module. It now says which Python version it needs.

## Upgrade

Refresh the installer to 3.5.0, run it in each checkout, and start a fresh agent session. Then rerun `doctor --live --workflow review-pr`. Saved models, launchers, and review settings carry over. A PR reviewed with an earlier version is reviewed once more because the reviewer instructions changed.

If your organization restricts Codex sandbox modes or Claude's built-in file tools, the live doctor is the check that shows it.

## Verification

The generated catalog, customization layers, and committed package checks passed, along with the package, runtime, transport, shared, and GitHub test suites. With a Claude launcher configured to block every MCP server, the live doctor passed for both reviewers and the adjudicator using Claude Code 2.1.326 and Codex 0.170.0. On the cross-file evaluation, both clients found and cited a broken caller outside the diff.

A complete two-model review ran against a live GitHub PR with this code and returned an adjudicated result. A fresh install and an upgrade from the published 3.4.1 archive both passed; the upgrade kept hosts, routing, verification, and the saved launcher.

Not exercised: a real managed machine. The `AGENTS.md` import was checked with headless Claude Code 2.1.329, not an interactive session.

## Install

Download **bstack-3.5.0.zip** and **SHA256SUMS**, verify the checksum, and extract the ZIP. From the extracted `bstack` folder, run:

```sh
python3 install.py --project /path/to/my-project
```

Use the same command to upgrade. Requires Python 3.11+ on macOS or Linux. To distribute an extracted release through a folder-based skill installer, select its root `bstack` skill and explicitly run setup. [Installation guide](https://github.com/bbishdotdev/ai-tools/blob/v3.5.0/bstack/INSTALL.md)
