# bstack 3.0.0

PR reviewers can search the whole repository without an extra worker setup. This release also restores portable session workflows and makes review feedback easier to act on.

## Breaking changes

**The default review security boundary changed.** Version 2.0.0 required an external isolation worker. Static review now uses BStack's bundled repository browser with general shell, filesystem, web, and unrelated integration tools disabled at the model interface. That is not OS isolation. The installed CLI, wrapper, and administrator-managed configuration remain trusted local components.

If you depend on OS-enforced isolation, keep an explicit vetted `worker` in `.bstack/review.json`, check its compatibility with the browser connection, and run `doctor --live` before unattended review. Running an app or tests still requires a separate credential-free runtime worker. A clean safety preflight does not authorize executing PR code. See the [security contract](https://github.com/bbishdotdev/ai-tools/blob/v3.0.0/bstack/engineering/review-pr/references/security.md).

## Changes

- Reviewers autonomously list, search, read, and compare complete pinned repository trees, including unchanged callers. The browser ships in the package, uses stdio, and needs no listening service or per-file approvals. Long patches and discussion remain readable through pagination.
- Reviews group findings by required action, explain the problem and impact, and give a separate next step. Named code links replace numbered evidence labels. Older published reviews remain readable after upgrading.
- Portable `automate-me`, `recall`, and `reflect` use scoped Codex, Claude Code, Cursor, and Grok sessions. Amp thread export requires confirmation that selected threads belong to the intended project.
- `worktree-cleanup` provides a read-only Git audit and asks before removing exact paths. Quarantined upstream playbooks and unused helpers stay in development sources, outside the consumer bundle. PR babysitting remains out of scope.
- Amp and Copilot have optional project skill bindings. Their hooks and headless review-model adapters are not implemented. The README's compatibility matrix separates skills, auto routing, PR workflows, and hooks across apps and CLIs.

## Upgrade

Refresh `install-bstack` or download this ZIP, then ask your agent to upgrade BStack in each project. Selected hosts, routing, verification settings, and private work are preserved. Stop local workspace writers first, then start a fresh agent session after setup.

```sh
python3 .bstack/package/scripts/bstack.py doctor --project "$PWD"
python3 .bstack/package/scripts/bstack.py doctor --project "$PWD" --live --workflow review-pr
```

The live review check spends model usage and tests the actual restricted launch. Add Amp or Copilot explicitly with `--hosts` when installing. On upgrade, pass the complete desired host list if adding either; omit the flag to preserve the existing selection.

## Verification

Source, catalog, package, installer, runtime, transport, layer, shared, and GitHub workflow checks passed. A fresh offline install and an upgrade from the published 2.0.0 ZIP passed, preserving hosts, routing, verification, project notes, and private work. The live restricted-launch doctor passed all three configured roles. Linux live checks with Codex and Claude Code exercised restricted browsing, unchanged-caller navigation, synthetic escape attempts, and the two-reviewer plus final-reviewer workflow. These checks do not establish macOS runtime behavior, desktop discovery, or live Amp/Copilot behavior. See [PR #21](https://github.com/bbishdotdev/ai-tools/pull/21) and [PR #22](https://github.com/bbishdotdev/ai-tools/pull/22).

## Install

Download **bstack-3.0.0.zip** and **SHA256SUMS**. Extract the ZIP and ask your agent to read its `SKILL.md` and install into your project, or run from the extracted folder:

```sh
python3 install.py --project /path/to/my-project
```

Use the same installer to upgrade. Requires Python 3.11+ on macOS or Linux. See [installation](https://github.com/bbishdotdev/ai-tools/blob/v3.0.0/bstack/INSTALL.md) for skills.sh and other options.
