# bstack 3.1.0

Use the same engineering and PR workflows across seven CLIs, with compatibility measured by real work instead of hand-edited badges.

## Changes

- Add native routing and PR guards for Amp and Copilot, and an OpenCode installer binding and plugin. Codex, Claude Code, Cursor, and Grok keep their existing integration paths.
- Name the selected playbook, verification policy, and PR helper directly so agents can find and follow the intended workflow. Compaction gets a specific instruction to reload missing context.
- Check skills, bug fixes, feature verification, ADR use, PR publishing, and compaction in disposable projects. A separate native guard probe must observe a denied raw PR command. Model quality is reported separately from tool integration.
- Preserve failed and quota-limited attempts in the results. An unsuccessful rerun can no longer leave an older Supported result under a fresh date.
- Contain generated-code grading, candidate Git commands, and file reads in a credential-free, network-isolated maintainer worker. Consumer installation and static PR review need no additional system packages.
- Fix Grok shell-tool detection and accept Copilot tool arguments as either an object or JSON text. Denial messages point directly to the installed PR helper.
- Let `to-pr` refresh an owned PR description with fresh overlap and ownership checks. An incomplete or flagged assessment restores draft status. A truly small PR, up to two files and 30 changed lines, can omit a visual.

See [PR #23](https://github.com/bbishdotdev/ai-tools/pull/23) for implementation and review.

## Upgrade

Run the newer installer in the existing project, then start a fresh agent session. Existing host selections, routing mode, and verification mode are preserved. To add Amp, Copilot, or OpenCode, pass the complete desired host list with `--hosts` or ask the installer agent to add that tool. Installation does not sign in to model providers or activate personal memory.

Use the installed `doctor` to check files and bindings. Before a multi-model workflow, run `doctor --project "$PWD" --live --workflow review-pr` through the installed controller to check the selected launchers and model access. Custom CLI wrapper commands remain configurable. See [installation and updates](https://github.com/bbishdotdev/ai-tools/blob/v3.1.0/bstack/INSTALL.md).

## Verification and limits

Package, layer, transport, installer, shared workflow, hook, guard, and GitHub-helper checks passed on Linux. Release verification includes a fresh seven-host install and an upgrade from the published 3.0.0 ZIP. Four containment canaries exercise hostile generated code, Git configuration, symlinks, and hook records.

Eighteen live native PR-guard probes passed: three each for Codex, Claude Code, Cursor, Grok, Amp, and OpenCode. Copilot's new probe could not run because the account reached its monthly provider quota; its PR-workflow cell remains Partial. Earlier Copilot publishing and compaction results include two completed repeats where quota prevented the third. The parser is locally checked with both supported argument formats.

These are recorded CLI integration results with selected models, not a guarantee that every model completes every task correctly. Desktop and interactive-app validation remains separate. The headless suite supplies project trust and full-access settings inside its outer test jail, so it does not establish native first-run trust or approval behavior. The fake forge checks workflow behavior, not live GitHub attachment permissions. Amp has no native compaction scenario.

Known maintainer limitation: bulk regrading and desktop/TUI evidence grading stop at the first malformed case instead of recording that case and continuing. Normal CLI evaluation records failures per case. This does not affect installed BStack workflows.

The Linux behavior-eval worker uses Bubblewrap only for maintainers running that suite. It is not shipped as a new consumer requirement. Static PR review still uses restricted repository tools, which are not an OS sandbox; running app code during review remains a separate optional worker configuration.

## Install

Download **bstack-3.1.0.zip** and **SHA256SUMS** from this release, verify the checksum, and extract the ZIP. Ask your agent to read its `SKILL.md` and install into your project, or run from the extracted folder:

```sh
python3 install.py --project /path/to/my-project
```

Use the same installer to upgrade. Requires Python 3.11+ on macOS or Linux. Neither the offline installer nor the skills.sh transport fetches newer upstream skills.
